# English Reading Studio

교재 사진 또는 영어 텍스트를 영국 영어 음성으로 바꾸고, 한 번씩 듣기를 기록하는 웹앱입니다.

## 사용 흐름

기본 리딩에는 첨부된 두 장의 교재 원본, 전체 전사문과 Emma 영국식 음성이 포함되어 즉시 들을 수 있습니다. 기본 자료는 배포 서버의 정적 파일과 서버 DB에 저장되며, 삭제하면 목록에서 사라지고 다시 생성되지 않습니다. 기본 자료 파일은 앱에 동봉된 프리셋이므로 소스에도 남습니다.

텍스트 직접 입력에서는 본문을 붙여넣고 **바로 음성 만들기**를 누르면 됩니다. 별도 확인 단계가 없으며 제목을 비우면 첫 여덟 단어를 제목으로 사용합니다.

사진 입력 흐름:

1. 새 리딩에서 제목과 사진을 추가합니다. 여러 장은 페이지 순서대로 선택합니다.
2. 설정에서 Google AI Studio의 Gemini API 키를 연결하고 사진의 본문을 추출합니다. 키는 현재 브라우저 탭의 sessionStorage에만 보관됩니다. 텍스트를 직접 붙여넣어도 됩니다.
3. 원본을 대조해 편집하고 확인 체크를 합니다. 불분명한 `[확인 필요]`는 먼저 수정합니다.
4. 영국 음성을 고르고 생성합니다. Kokoro-82M은 브라우저 Web Worker의 WASM에서 실행됩니다. 첫 사용에는 약 100MB 이상의 모델·런타임 다운로드가 필요합니다.
5. 생성이 끝나면 제목·본문·원본 사진·음성을 서버에 저장합니다. 확정된 콘텐츠는 수정할 수 없습니다. 새 항목 추가와 삭제만 지원합니다. 목표 듣기 횟수는 따로 바꿀 수 있습니다.
6. 한 번 듣기를 누를 때마다 한 번 재생합니다. 일시정지 후 이어듣기가 가능하고, 정지하거나 중간에 종료하면 횟수에 포함하지 않습니다. 음성이 끝까지 재생되면 완료 횟수가 1 증가합니다. 자동 반복은 없습니다.

본문 전체를 스크롤로 표시하며 단어·문장별 자막 동기화를 주장하지 않습니다. 시작과 끝에는 C5–E5–G5–C6(도–미–솔–높은 도) 벨 효과음을 음성 파일 자체에 포함합니다. 다운로드에도 효과음이 포함됩니다.

## 서버와 접근

로그인은 스도쿠·Brush와 같은 Supabase 프로젝트의 Google OAuth(PKCE)를 사용합니다. 서버는 Supabase `/auth/v1/user` 응답으로 계정과 Google 연결·이메일 확인 여부를 검증합니다. 업로드·사진 인식·삭제는 `hyojong.yee@gmail.com`, `yelea.nho@gmail.com`만 허용하며 브라우저의 사용자 메타데이터는 권한 판단에 사용하지 않습니다. 다른 Google 계정은 보관함 조회와 본인 듣기 기록·목표 변경이 가능합니다. 비로그인 사용자는 기본 자료와 기기 내 기능을 사용합니다. 듣기 기록은 계정별로 분리됩니다. 이전 익명 기록은 첫 번째 허용 계정에 한 번 귀속합니다.

자료는 서버 D1(제목·본문·목표·완료 기록)과 R2(원본 사진·음원)에 저장됩니다. 공개 GitHub에는 앱 소스와 사용자 요청으로 탑재한 기본 자료만 보관합니다. 사용자 업로드와 API 키는 커밋하지 않습니다. OAuth 완료 후 미디어 요청을 위한 HttpOnly 쿠키를 설정하고, API마다 인증을 다시 검증합니다. Supabase에 정확한 앱 원점의 `/` 리디렉션 URL을 등록해야 합니다. 배포 플랫폼의 기존 소유자 비공개 접근은 별도이며 이 소스로 변경되지 않습니다.

서버의 API와 DB 트리거가 확정 콘텐츠 수정 요청을 차단합니다. 완료 기록 UUID의 고유 제약으로 재전송·다중 요청이 횟수를 중복 가산하지 않습니다. 오프라인 중 완료한 기록은 기기에 잠시 보관했다가 연결 시 전송합니다. 삭제에는 제목 재입력이 필요합니다.

## 녹음과 내보내기

- Space는 라이브러리에서 재생·정지합니다. 입력창·대화상자에는 영향을 주지 않습니다. 녹음실이 열리면 녹음실 음원의 재생·정지에만 사용합니다. 녹음 자체는 버튼으로 시작·종료합니다.
- 리딩 화면의 **녹음실 · 음원 불러오기**에서 기기 음원을 재생하거나 반주로 사용합니다. 허용된 계정은 제목·본문과 함께 새 리딩으로 서버 저장할 수 있습니다. 저장 뒤 내용은 수정할 수 없습니다. MP3·WAV·M4A·OGG·FLAC·WebM을 지원하며 기기 브라우저가 재생할 수 있어야 합니다. 업로드 음원의 도미솔도 알림은 앱에서 재생할 때 붙습니다. 원본 파일은 그대로 보관합니다.
- 마이크 권한을 허용한 뒤 유선·블루투스·기본 마이크를 선택합니다. 연결 여부와 목록은 운영체제·브라우저 지원에 따릅니다. 마이크와 음원을 Web Audio로 혼합하며, 두 볼륨을 녹음 중에도 독립 조절합니다. 마이크 모니터링은 하지 않습니다. 합성 신호에는 피크 완화기를 적용합니다.
- 녹음은 브라우저 MediaRecorder의 지원 형식(Opus 또는 AAC)으로 기기에만 임시 보관됩니다. 완료한 녹음의 볼륨을 다시 분리 조절하지는 않습니다. 다운로드 전에 페이지를 닫으면 녹음은 사라집니다.
- FFmpeg.wasm 단일 스레드로 MP3 320kbps 또는 MP4 H.264 1920×1080 + AAC 목표 320kbps로 출력합니다. MP4 정지화면은 전체 본문이나 선택한 원본 한 쪽입니다. 긴 본문은 글자가 작아질 수 있습니다. 음질은 원본·입력 장치 품질에 의존하며 비트레이트가 원본 정보를 복원하지는 않습니다.
- 첫 변환 때 약 32MB의 코어를 CDN에서 내려받습니다. 변환은 서버에 녹음을 보내지 않고 기기에서 처리합니다. 필요한 메모리·변환 시간은 음원 길이에 따라 늘어납니다. 원본 음원을 녹음 없이 변환하는 메뉴도 제공합니다.

## 무료 이용 범위

- Kokoro는 로컬 실행이므로 음성 생성 API 요금이 없습니다. 사용자 기기의 메모리·CPU를 사용합니다.
- Gemini는 지원되는 계정·모델의 무료 제공량 내에서 사용합니다. 한도 도달 시 자동 유료 전환하지 않고 오류를 표시합니다. 과금 여부는 사용자가 선택한 Google 프로젝트의 결제 설정에도 달려 있습니다. 무료 이용 데이터는 Google 제품 개선에 사용될 수 있습니다.
- 서버 호스팅·저장소는 호스팅 제공자의 용량·요금 정책이 적용됩니다. 무제한 무료 저장을 보장하지 않습니다.

## 개발과 배포

Node 22.13+와 프로젝트 pnpm 버전을 사용합니다. 패키지와 잠금 파일을 함께 보관합니다.

```bash
pnpm install
pnpm dev
pnpm exec tsc --noEmit
pnpm test
pnpm db:generate
pnpm build
```

호스팅 바인딩은 `.openai/hosting.json`의 `DB`(D1), `BUCKET`(R2)입니다. Sites 원본 저장소·배포 워크플로가 이 바인딩과 마이그레이션을 적용합니다. Github의 `english` 저장소는 사용자가 지정한 소스 사본이며 GitHub Pages만으로 서버 API는 실행되지 않습니다. 선택적으로 서버 환경변수 `GEMINI_API_KEY`를 설정하면 브라우저에 키를 입력하지 않고 사진 인식을 사용할 수 있습니다. 키 값은 소스에 기록하지 않습니다.

본문 8,000자, 사진 최대 8장(각 10MB), 생성 WAV·업로드 음원 최대 40MB, 전체 요청 65MB를 제한합니다. 사진 인식에는 축소본을 전송하고 저장에는 원본 파일을 사용합니다. 흐림·가려짐·기울기·모델 환각으로 인식 오류가 남을 수 있으므로 생성 전에 원문을 확인해야 합니다.
